Deterministic price inference from DB comparables — price-comps-v1

todo/COMMERCIAL.md Phase 2 — the engine that fills price gaps from what the catalog already knows. No LLM, no RNG, no clock read: a least-squares fit of log10(price) vs log10(spec) up a same-family product ladder, with a distance-weighted KNN fallback, and a chain of honesty gates that ends in None rather than a junk figure. Output is a SourcedFigure (PR #331) carrying the sorted comparable IDs and method version — rerun against the same DB snapshot and you reproduce the figure bit-for-bit.

▮▮▮ METHOD ▮▮▮
  1. M-1

    Rung 1 — family ladder (log-log fit)

    price-comps-v1:family-ladder — comparables sharing the target's manufacturer AND product_family (both non-empty), with ≥3 priced points carrying the type's primary sizing spec. Industrial pricing is power-law in size, so a least-squares fit of log10(price) vs log10(spec) interpolates the target's price exactly on a clean ladder.

  2. M-2

    Rung 2 — KNN fallback

    price-comps-v1:knn — distance- weighted median (weight 1/(d + 0.1)) of the k≤8 nearest priced comparables by RMS distance in log10-spec space, over whichever dominant specs the target carries (≥1 shared spec required; distance ties break on product_id). Pool is same product_type, msrp.unit == "USD", msrp.value > 0, target excluded.

  3. M-3

    Dominant sizing specs per type

    motor (rated_power, rated_torque); drive (rated_power, rated_current); gearhead (max_continuous_torque, gear_ratio); electric_cylinder (continuous_force, stroke); linear_actuator (max_push_force, stroke); robot_arm (payload, reach); contactor (conventional_thermal_current, rated_operational_voltage_max). ValueUnit uses the scalar, MinMaxUnit the midpoint. Units are never converted — the store is canonical per key, so a comparable whose spec unit differs from the target's is dropped, not converted.

  4. G-1

    Honesty gates — None over junk

    Used comparable pool < 3 → no estimate. p75/p25 price dispersion of the used pool > 4× → no estimate. Family ladder would extrapolate beyond [min_spec/2, max_spec*2] → fall back to KNN, which then applies its own gates — so the chain ends in None, never a junk figure.

  5. R-1

    Replicability by construction

    Output is a SourcedFigure (confidence="inferred", observed_range = p25–p75 of the used prices) with a single db_inference citation carrying the sorted comparable product_ids and the method version string. The pool is sorted by product_id before any float arithmetic, ties break on product_id, there is no RNG and no clock read (retrieved_at is injected by the caller). The property suite pins bit-identical output under input permutation.

  6. C-1

    CLI — dry-run by default, prod excluded

    ./Quickstart price-infer [--stage dev|staging] [--type X] [--limit N] [--dry-run|--apply] [--refresh] — dry-run prints a per-estimate table (part number, estimate, p25–p75 range, method, comparable count) so an operator can eyeball the reasoning. --apply writes price_estimate onto the row; msrp is never touched. Prod is not an accepted stage — estimate writes to prod are out of scope for this tool.
