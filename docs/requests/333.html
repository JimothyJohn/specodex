Commercial-first UI — chips, popovers, badges, balance control, vendor drawer

todo/COMMERCIAL.md Phase 3 — the display layer for the provenance schema (PR #331) and the inference engine's output (PR #332). Every commercial figure in the table now says what it is and where it came from: listed prices get a LISTED confidence chip, estimates render muted with a tilde and their own tier, and every chip opens a source popover with the citation trail. ▮▮▮ PER-SURFACE BEFORE → AFTER ▮▮▮
  1. S-1

    Price cell

    Before: bare number or empty cell; no way to tell where a price came from. After: a listed price renders as before plus a LISTED ConfidenceChip; click → SourcePopover citing msrp_source_url + msrp_fetched_at (no source URL → "listed — catalog extraction", citing the datasheet_url). No listed price but a price_estimate → ~$1,240 styled muted/italic + confidence chip + popover. Neither → —. Resolution order (listed > estimate > absent) is a pure function in utils/commercial.ts, unit-tested; the two are never merged.

  2. S-2

    Lead-time cell + stocked badges

    Before: humanized enum text ("In Stock"), no provenance. After: in_stock / limited → compact STOCKED badge whose popover cites availability_source_url + availability_fetched_at; back_order / out_of_stock / pre_order / discontinued → corresponding muted badges; listed lead_time renders its value; lead_time_estimate renders ~N weeks + chip; else —.

  3. S-3

    Source popover

    New ui/SourcePopover. Each citation: kind label, publisher hostname (derived from the URL), retrieval date, verbatim excerpt in quoted style, and a "View source" <ExternalLink>. db_inference citations read "Estimated from N comparable products (method X)" — ids are counted, not linked, because no per-product route exists.

  4. S-4

    Commercial ⇄ Technical balance

    New BalanceToggle — segmented COMM / BAL / TECH control in the header next to the density toggle, persisted under specodex.columnBalance. Commercial → the commercial band (price, lead time, warranty) pins first and a price-ascending default sort is seeded (removed on the way out only if the user hasn't touched it); Technical → specs first with the commercial band trailing last; Balanced → today's default. Implemented by extending orderColumnAttributes (the PR #285 mechanism) with a balance parameter — no parallel ordering path.

  5. S-5

    Vendor drawer

    Before: manufacturer cells were inert text. After: clicking a manufacturer opens an app-native drawer reading src/data/vendors.json (seeded {} — the registry + real cited data ship in PR #334) through a tolerant accessor. No entry → the honest empty state: "No published commercial facts on file for <name>. Facts appear here only with a verifiable public citation." Entries render each fact with its citations through the same SourcePopover. No ratings, no stars, no invented copy.

  6. S-6

    Filters — stocked chip + estimates opt-in

    Stocked-only quick chip in the page toolbar — a plain FilterCriterion (availability ∈ {in_stock, limited}) through the existing multi-select matching. Price filters gain a per-filter includeEstimates flag (default off — listed prices only); when on, rows without msrp fall back to price_estimate.value, and a listed price always wins over the estimate. Surfaced as an ~est toggle on the price column header (both densities).

▮▮▮ CONVENTIONS HELD ▮▮▮

No native chrome: Tooltip / ExternalLink primitives throughout, portaled popovers and drawer with outside-click + Escape dismissal, .scrollable for themed scrollbars — the style drift gates pass (SourcePopover's header prop is named heading to stay clear of the title= grep). Every new component ships a sibling .css imported by the component; App.css untouched.
